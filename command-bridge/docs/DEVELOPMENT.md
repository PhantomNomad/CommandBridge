# Preview PDF / Download PDF buttons - change notes

## How it works now
Every form page shows one "Form Actions" card with **Preview PDF** and **Download PDF**, both generated by
`render_ics_form_actions()` in `includes/form_action_buttons.php`. The links are derived from the form code:

- Download PDF -> `/forms/<form>/pdf.php?incident_id=..&op_id=..`            (sent as an attachment)
- Preview PDF  -> `/forms/<form>/pdf.php?incident_id=..&op_id=..&preview=1`  (opens inline in the browser tab)

`includes/pdf/pdf_request.php` holds the shared helpers (`ics_pdf_preview_requested()`, `ics_pdf_context()`, ...).
To add the buttons to a new form: create `forms/<form>/pdf.php` that honours `preview=1`, and call
`render_ics_form_actions([...])` on the page. No URLs need to be passed.

## Fixed
- Preview used to open `index.php?view=print` (the form page again) or "not implemented". It now shows the real PDF.
- Duplicate button rows removed (old `.actions` block, status-bar buttons, "Export PDF" / "Generate PDF" links).
- ICS 230 had no action bar; it now has one (plus preview/download of the Meeting Posting PDF).
- Forms that sent their PDF inline when "downloading" (204, 205, 206, 208, 214, 215A, 218, 230) now really download.

## New PDF generators (official ICS Canada template filled via pdftk, same method as ICS 202/205)
ICS 205A, 207, 210, 211, 213. Multi-page where the data exceeds one template page (205A 34 rows, 210 28 rows, 211 18 rows).
ICS 211 uses `forms/ics211/Ics211TemplateFieldMap.php`, generated from field positions because the template's field names are generic.

## Template fix (ICS 205 "could not be generated")
ICS203, 204, 205, 206, 208, 214 and 220 in `assets/pdf/official/` were encrypted (owner-password, AES-256 / R6), which
pdftk-java cannot open. They were decrypted with `qpdf --decrypt` (fields unchanged). If a template is ever replaced,
run `qpdf --decrypt` on it first.
